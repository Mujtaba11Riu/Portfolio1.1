Security Threat Analyzer: Automating STRIDE & DREAD Risk Assessment with Live CVE Data

📅 April 28, 2026 ⏱ 6 min read 🔒 Project Showcase

During my 4th semester end project at Riphah International University, I developed a security desktop application that brings industry‑grade threat modeling to your fingertips. The Security Threat Analyzer is an interactive Python tool that automatically identifies security threats (using STRIDE), quantifies their severity (DREAD scoring), and enriches the findings with real‑world CVE data from the NIST NVD API—all packaged in a user‑friendly interface.

🚀 Project Goal
To create a centralized, easy‑to‑use threat modeler that helps security analysts and students quickly visualize potential risks in a system (web apps, servers, networks) without manually heavy spreadsheets.

Project Architecture Overview

The application follows a modular, layered architecture. The GUI (built with Tkinter) serves as the control center, where users enter system details. This input is then processed by three core engines, each handling a distinct part of the threat assessment process:

⚙️ Core Modules
🔄 STRIDE Analyzer: Maps services to threat types (Spoofing, Tampering, Repudiation, Info Disclosure, DoS, Elevation of Privilege).
📊 DREAD Scorer: Quantifies risk with damage, reproducibility, exploitability, affected users & discoverability.
🌐 CVE Lookup: Fetches real‑world vulnerability intelligence via NIST NVD API (with offline cache).
📄 Report Generator: Exports professional PDF reports with all findings.

STRIDE Threat Analysis Engine

The STRIDE module lets users select active services (e.g., FTP, SSH, HTTP, RDP) and specify whether authentication and encryption are in use. Based on this, it cross‑references pre‑defined threat rules and flags relevant threats. For example, if the user indicates no encryption, the tool automatically adds "Information Disclosure" to the list.

def analyze(self, services, has_auth, has_encryption):
    # Step 1: Check each selected service against threat rules
    for service in services:
        if service in THREAT_RULES:
            for threat_type, description in THREAT_RULES[service].items():
                self._add_threat(threat_type, service, description)
    
    # Step 2: Add threats related to missing authentication
    if not has_auth:
        for threat_type, description in NO_AUTH_THREATS.items():
            self._add_threat(threat_type, "No Authentication", description)
    
    # Step 3: Add threats related to missing encryption
    if not has_encryption:
        for threat_type, description in NO_ENCRYPTION_THREATS.items():
            self._add_threat(threat_type, "No Encryption", description)

This logical approach ensures that even if a user is not an expert, the application can still guide them toward potential security gaps.

DREAD Scoring: Quantifying the Risk

Once threats are identified, the DREAD Scorer steps in to quantify their severity. Each threat is scored (1–10) on five factors, which are then averaged to produce an overall risk level (Critical, High, Medium, Low). The module also calculates an overall risk score for the entire system.

DREAD_SCORES = {
    "Information Disclosure": {
        "Damage": 9, "Reproducibility": 9,
        "Exploitability": 8, "Affected Users": 9,
        "Discoverability": 8
    },
    "Elevation of Privilege": {
        "Damage": 10, "Reproducibility": 6,
        "Exploitability": 7, "Affected Users": 8,
        "Discoverability": 5
    }
}

The weighted averages help analysts prioritize which threats to address first—extremely useful when working under time or budget constraints.

Real‑World Context via CVE Lookup

The CVE module connects to the NIST National Vulnerability Database (NVD) and fetches actual vulnerability data based on the services entered by the user (e.g., "FTP", "SSH"). The results include CVE IDs, descriptions, CVSS scores, and severity levels. To respect API rate limits and improve responsiveness, the module implements a local JSON cache—reducing repetitive network calls.

def search(self, keyword, max_results=3):
    # First, check the local cache
    if keyword in self.cache:
        return self.cache[keyword][:max_results]

    # If not cached, query the NVD API
    params = {"keywordSearch": keyword, "resultsPerPage": max_results}
    response = requests.get(self.API_URL, params=params, timeout=10)
    if response.status_code == 200:
        results = self.parser.parse(response.json())
        self.cache[keyword] = results      # Store in cache
        self._save_cache()
        return results
    else:
        return self._get_offline_data(keyword)   # Fallback to sample data when offline
⚠️ Offline Support
Even without an internet connection, the CVE engine falls back to a sample dataset (covering common services like FTP, SSH, HTTP). This ensures the application remains functional for classroom or offline scenarios.

Interactive GUI with Custom Branding

The front end uses Tkinter, providing a clean, dual‑panel interface reminiscent of professional security tools. The left panel collects user inputs (services, checkboxes), while the right panel displays results. Features include:

  • Custom shield‑lock icon drawn dynamically using Pillow—adding a professional, brand‑centric feel.
  • Threaded analysis to prevent the UI from freezing during API calls.
  • Report generation using ReportLab, allowing users to export findings as polished PDFs.
